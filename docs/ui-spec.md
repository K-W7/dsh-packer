# dsh-packer · UI 规格

> 现行版本：**v0.7.0**（本文取代原 `docs/ui-v060-spec.md`；v0.6.0 定稿的命名与视觉纪律仍然有效，已并入本文）。
>
> 用户 2026-10-25 定稿：结构认可（清点 → 打包 → 恢复 → 结果，一页走完），**但命名必须贴合插件本身**——
> 这是「配置打包器 / 迁移」，不是"搬家"。所以以下比喻词一律不用：箱子、封箱、开箱、家当、对账、封箱单、搬运。

## 1. 命名对照（全局替换，代码里也别写比喻词）

| 概念 | 统一叫法 |
|---|---|
| 产品的包 | **配置包**（列表处就叫「配置包」） |
| 已有包列表 | **配置包**（区块标题「已有的配置包」） |
| 创建动作 | **打包** |
| 恢复动作 | **恢复** |
| 本机可打包内容 | **打包内容**（区块标题「打包内容」） |
| 单个包的信息/凭据 | **包信息**（区块标题「包信息」） |
| 打包完成 | **打包结果** |
| 恢复完成 | **恢复结果** |
| 包内 vs 本机对比 | **差异对比** |
| 打码模式 | **脱敏**（选项文案「清理后打包（脱敏）」） |
| 上锁 | **加密**（勾选「加密（设置口令）」） |
| 待人工处理项 | **待确认项** |
| 校验 | **完整性校验** |
| 体积合计 | **合计** |

## 2. 页面结构（一页，四个区块 + 顶部状态条）

1. **标题区**：标题「配置打包器」，副标题「把本机的 DSH 配置打包备份，换机器或换平台时恢复。」；右侧状态条 = 包目录（点一下复制；显示时用 `<用户目录>` 遮蔽本机路径）+ 占用体积。
2. **已有的配置包**：列 = 包名 / 时间 / 内容 / 大小 / 操作（恢复、包信息、重命名、删除）。空态：一句提示 + 引导去打包。
3. **打包内容**：表格列 = 内容 / 说明 / 体积 / 是否带上（勾选）。表格下：合计体积 + 一句提醒（换机器必须带已安装插件）。
4. **打包选项**：三个单选项（原样打包 / 清理后打包（脱敏）/ 加密（设置口令））+ 口令输入（勾加密才出现，弱口令禁用主按钮）+ 扫描结论 + 「先预览」「开始打包」+ 进度条与取消 + 打包结果卡。
5. **恢复**：选择配置包（下拉）或填路径 → 「导入检查」→ **差异对比**表（内容 / 包内 / 本机 / 处理方式）→ 模块勾选 + 三种冲突策略 → 「开始恢复」→ 进度 → **恢复结果**明细（覆盖/新增/跳过/待确认/失败）+ 备份目录 + 一键撤回。

弹窗四个，全部复用同一套 `Modal`：**包信息**（含完整性校验结果）、**口令**（打开加密包时输入）、**重命名**、**确认**（删除等破坏性动作）。

## 3. 前端源码结构（v0.7.0 起）

界面不再是单个大文件。**`lib/client.js` 是构建产物，禁止手改** —— 改源头，再跑构建。

| 层 | 文件 | 职责 |
|---|---|---|
| 契约 | `types.ts` | 与 `/packer/api` 一一对应的数据类型 |
| 纯函数 | `format.ts` | 体积 / 时间 / 路径遮蔽等纯展示逻辑（可单测） |
| 通道 | `api.ts` | `apiFetch`（统一错误码 `ApiFailure`） |
| 状态 | `model.ts` | `usePacker()`：全部状态、动作与派生值（`react.useMemo`） |
| 组件 | `ui.ts` | 设计系统：`Section` `Button` `Check` `Field` `Modal` `Progress` `ResultCard` … |
| 文案 | `copy.ts` | 全部中文文案（含中英切换入口 `text()`） |
| 样式 | `styles.ts` | CSS-in-JS，只依赖 `--pk-*` / `--dsw-alias-*` 令牌 |
| 分区 | `view/packs.ts` `view/contents.ts` `view/options.ts` `view/restore.ts` | 四个区块，只消费 `model`，不自己发请求 |
| 弹窗 | `view/dialogs.ts` | 四个弹窗 |
| 装配 | `index.ts` | 主题 + 状态 + 分区 + 弹窗；`apply(ctx)` 注册 `settings.section` / `packer-settings` / `order: 60` |

构建：`npm run build`（esbuild，`react` 保持 external 由宿主提供，产物包成 `__ModuleLoader.load` 的 CommonJS 工厂）。
CI 在构建后跑 `git diff --exit-code -- lib/client.js`：**改了源头却不重新构建 = 流水线红**。

## 4. 接口落点（每个按钮都必须真有后端）

| 界面动作 | 端点 |
|---|---|
| 首屏 / 刷新 | `GET /status` |
| 先预览 | `POST /create { dryRun: true }` |
| 开始打包 | `POST /create` → `GET /jobs/:id` → `POST /jobs/:id/cancel` |
| 包信息 | `GET /packs/:name/info`（含完整性校验 `verify`） |
| 重命名 | `POST /packs/rename` |
| 删除 | `DELETE /packs/:name`（进系统回收站；不支持的平台回报 warning） |
| 导入检查 | `POST /restore/import` |
| 开始恢复 | `POST /restore/apply` → `GET /jobs/:id` → `POST /jobs/:id/cancel` |
| 撤回 | `POST /restore/rollback` |

**不得新增接口调用。** 缺字段时显示「—」并标注「接口未返回」，绝不编造。

## 5. 文案纪律

- **禁止 emoji 与图标字符**（✓、⚠、📦 等一律不用）：状态用文字（已带上/相同/跳过/待确认/已加密）与 CSS 细线、色块表达。
- 不出现字段名（`memoryDb`、`presets`、`pack` 这类）；用产品语言（记忆数据库、配置与预设）。
- 中文单语；数字与单位统一（KB/MB，保留一位小数）。
- 出网内容不带本机绝对路径：需要显示时用 `<用户目录>` 遮蔽。

## 6. 视觉

沿用 v0.5.x 令牌：品牌琥珀（亮 `#F59E0B` / 暗 `#FBBF24`）只用于主按钮、选中态、进度条、焦点描边；其余走 `--dsw-alias-*` + `--pk-*` 兜底；4/8px 栅格；字号只用 12/14/16/20；行高 ≥1.6；深色底 `#0F1115`～`#1A1D23`、文字 `#E8EAED`；`:focus-visible` 可见描边；`prefers-reduced-motion` 关闭动效；空/载/错三态齐全。

## 7. 无障碍（v0.7.0 新增，逐条由测试守住）

- 弹窗：`role="dialog"` + `aria-modal="true"` + `aria-labelledby`，打开时把焦点移进弹窗、Tab 在弹窗内循环（focus trap）、Esc 关闭、关闭后焦点还原到触发元素；
- 进度条：`role="progressbar"` + `aria-valuenow`（不确定态不写 `aria-valuenow`）；
- 表格：`th` 一律带 `scope="col"`；
- 复制按钮、提示条：`aria-live` 播报结果；
- 仅供读屏的补充说明用 `.pk-sr`（视觉隐藏但不移除）。

## 8. 工程约束

- 改界面 = 改 `src/client/**` 下的 TypeScript，然后 `npm run build`；`lib/client.js` 产物同步与 `tsc --noEmit` 都由 CI 校验。
- 业务状态只放 `model.ts`；视图不持有跨区块状态、不直接发请求。
- 测试：`tests/client-render.test.mjs`（构建产物可加载 + 首屏 SSR + 无障碍属性）、`tests/client-dom.test.mjs`（jsdom 真挂载：勾选联动、弱口令禁用、弹窗焦点与 Esc、取消不触发删除、下拉与手填互斥）。
- 「先预览」与「开始打包」打的是同一个 `/create`，后端按内容指纹缓存扫描结果（`docs/platform-support.md` 与 `lib/privacy.mjs` 文件头有说明），因此界面上连点两次不会把同一批文件扫两遍。
